# DanaQR

A Palm OS 4.1 application for the **AlphaSmart Dana** that converts text into
QR codes, so you can move text off the device and onto a phone without a
cable, IrDA, or SD card shuffle.

Workflow:

1. Select text in AlphaWord, copy it.
2. Launch **DanaQR**.
3. Press **Paste** (or Ctrl+V into the field) to load the clipboard.
4. Press **Gen** to encode. Long text is split into multiple QR frames.
5. **Cycle** through the frames automatically, or **Next** to step manually.
6. Scan each frame with any QR reader on your phone.

Text longer than a single QR code can hold is split into numbered chunks
(`Q01/05: ...`) and cycled on screen. A scanning app that supports multi-frame
reading (e.g. *QRScan*) can collect all of them; a plain single-frame reader
will capture whichever frame is visible when you hit the shutter.

## AI disclosure

The initial codebase was generated by an AI assistant at the request of the
maintainer. The maintainer then debugged the build, fixed several functional
bugs, and tested the result on real hardware (AlphaSmart Dana, Palm OS 4.1).
The code works but has not been reviewed for style or idiomatic Palm OS
conventions. Contributions and corrections are welcome.

## Requirements

- An AlphaSmart Dana running Palm OS 4.1 (or a Palm OS 4.x emulator such as
  POSE).
- A Linux or WSL2 host for building. The instructions below assume Ubuntu
  20.04 ("focal") on WSL2, which is what the project was developed against.
- The `prc-tools` cross-compiler for m68k, the Palm OS SDK headers, and
  `pilrc` + `build-prc` for resource compilation and packaging.

## Building

### 1. Install the toolchain

The most reliable path is `prc-tools-remix`, which ships prebuilt Debian
packages for recent Ubuntu releases:

```
wget https://github.com/jichu4n/prc-tools-remix/releases/download/v2.3.5/prc-tools-remix_2.3.5.focal_amd64.deb
wget https://github.com/jichu4n/pilrc/releases/download/v2.3.90/pilrc_3.2.90.focal_amd64.deb

sudo dpkg -i prc-tools-remix_2.3.5.focal_amd64.deb
sudo dpkg -i pilrc_3.2.90.focal_amd64.deb
```

Adjust the release version and distro codename if you're on a newer Ubuntu.
If the packages don't exist for your release, build from source — see the
prc-tools-remix repository for instructions.

### 2. Install the Palm OS SDK

The compiler on its own cannot find the SDK headers; you also need the SDK  
files and the `palmdev-prep` registration step.

```
git clone https://github.com/jichu4n/palm-os-sdk.git
cd palm-os-sdk
```

The repo contains a setup script that installs to /opt/palmdev

```
sudo bash ./setup-sdk.sh
sudo palmdev-prep
```

`palmdev-prep` scans `/opt/palmdev` and writes the SDK configuration that  
`m68k-palmos-gcc` reads. It should report something like:

```
Checking SDKs in /opt/palmdev
  sdk-4   headers in 'include', libraries in 'lib'
  sdk-5r4 headers in 'include', libraries in 'lib'
...
When GCC is given no -palmos options, SDK '5r4' will be used by default
```

### 3. Build

```
make clean
make
```

The output is `DanaQR.prc` in the project root. Copy it to the Dana and launch it  
from the application launcher.

## Project layout

```
DanaQR.rcp              PilRC resource script (form, buttons, alerts, menu)
Makefile                prc-tools build
src/main.c              Application entry, form handling, clipboard loading
src/chunker.c/.h        Splits long text into headered frames
src/qr_render.c/.h      Draws a QR code into a rectangle on screen
src/qrcode.c/.h         QRCodeGenPort (MIT) -- QR encoder, C90-compatible
src/assert.h            Minimal assert shim for the Palm OS toolchain
```

`src/DanaQR_rsrc.h` is generated by `pilrc` during the build and is not  
checked in.

## Configuration

Two values must agree with each other; both are in headers and require a  
rebuild if changed:

-   `QR_MAX_VERSION` in `src/qr_render.h` — the QR version the encoder targets.  
    **Currently 10.** Higher versions pack more text per frame but make each  
    module physically smaller on the 160×160 screen, which hurts scannability.
    
-   `CHUNK_PAYLOAD_MAX` in `src/chunker.h` — the number of payload bytes per  
    frame. **Currently 180**, matched to v10 + ECC LOW. If you raise  
    `QR_MAX_VERSION`, raise this too, and vice versa. A mismatch causes the  
    encoder to fail silently and produce unreadable frames.
    

`CYCLE_MS` in `src/main.c` controls how long each frame stays on screen  
during automatic cycling. Raise it if the phone has trouble locking on  
before the frame advances.

## Known limitations

-   **Stack constraints.** Palm OS 4 gives applications a small stack, and the  
    QR encoder allocates several hundred bytes of working memory during  
    encoding. Version 11 and above cause a stack overflow on real hardware and  
    in the emulator. Version 10 is the practical maximum. Some emulators  
    (POSE) have a smaller default stack than the Dana itself and may crash at  
    version 8 or 9 where real hardware would not.
    
-   **Single-frame scanning.** Multi-frame readers are not universally  
    supported. Most phone cameras will only capture the frame that happens to  
    be on screen. For text that fits in one frame, no cycling is needed.
    
-   **Clipboard size.** The Palm OS clipboard is limited to a few kilobytes.  
    Very large AlphaWord selections may fail to copy, or be truncated.
    
-   **Chunk count.**  `CHUNK_MAX_COUNT` in `src/chunker.h` is 99, matching the  
    two-digit sequence number in the frame header. Longer documents require  
    widening the header format.
    
-   **Contrast and lighting.** The Dana's LCD has modest contrast. Scanning  
    works best under decent lighting, with the phone held steady and square to  
    the screen.
